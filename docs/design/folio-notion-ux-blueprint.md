# Folio: Notion 사용성 청사진

## 제품의 자리

Folio는 Markdown을 배우거나 Obsidian 플러그인을 설정하지 않아도 바로 쓸 수 있는 공용 노트
제품이다. 파일은 사람이 읽을 수 있는 Markdown으로 남기고, 글을 쓰는 순간에는 Notion의 가장
좋은 사용성을 가져온다. 설정 화면을 찾아다니는 대신 커서 자리에서 다음 행동을 발견한다.

> 빨리 적고, 바로 다시 찾는다. 파일은 계속 단순하게 남는다.

Notion의 블록 데이터베이스를 복제하지 않는다. Notion을 쉽게 만드는 입력 문법만 가져와
로컬 우선 Markdown 편집기에 맞춘다.

## 지금 가진 것

- `@today`, `@tomorrow`, `@yesterday`로 글의 흐름을 끊지 않고 날짜를 넣는다.
- `/due`로 저장 문법을 직접 쓰지 않고 할 일의 기간을 붙이거나 바꾼다.
- 폴더 트리, 달력, 템플릿, 휴지통, 서식, 백링크, 아웃라인, 그래프, 태그, 읽기 화면이 있다.
- 내용은 독자 포맷이 아니라 평범한 Markdown으로 남는다.

다음 단계는 도구막대를 하나 더 만드는 일이 아니다. 먼저 어디에 적었는지 기억하지 않아도
문서를 다시 찾게 만들고, 그다음 사용자가 타이핑하는 자리에서 기존 기능을 발견하게 한다.

## 지금과 목표

| | 지금 | 목표 |
|---|---|---|
| 다시 찾기 | `Ctrl-K`와 `Search Space`는 있지만 터치 진입과 제목·본문 검색 품질을 재지 않았다 | 제목과 본문을 한 검색창에서 찾는다 |
| 결과 판단 | 문서를 열어 봐야 원하는 내용인지 안다 | 검색어가 나온 문장과 위치를 결과에서 미리 본다 |
| 자주 쓰는 문서 | 트리에서 다시 찾아간다 | 검색 전부터 최근 수정 문서가 보인다 |
| 없는 문서 | 검색과 새 문서 만들기가 갈린다 | 결과가 없으면 같은 자리에서 새 문서를 만든다 |
| 날짜 입력 | `@today` 등 세 가지가 이미 된다 | 현재 기능을 유지하고 검색·페이지 연결에 집중한다 |

## 사용 경험 원칙

1. **다시 찾을 수 있어야 적는 것이 쌓인다.** 제목을 몰라도 본문의 기억나는 말로 찾는다.
2. **커서가 명령 화면이다.** `@`, `/`, `[[`를 입력하면 그 문맥에 맞는 다음 행동이 나타난다.
3. **사용자는 뜻을 고르고 Folio가 문법을 쓴다.** 화면에서는 `내일`을 고르고 파일에는
   `2026-09-12` 또는 `📅 2026-09-12`가 남는다.
4. **결과를 언제나 사람이 확인할 수 있다.** Folio가 없어도 파일을 읽고 고칠 수 있다.
5. **키보드와 터치를 같은 길로 본다.** hover나 데스크톱 단축키로만 되는 기능은 미완성이다.
6. **설정보다 쓰면서 배운다.** 빈 줄, 빈 페이지, 제안 메뉴가 사용 중에 제품을 가르친다.

## 문서 찾기

`⌘K` 또는 `Ctrl-K`로 어디에서나 같은 검색 화면을 연다. 모바일에서는 홈 화면을 아래로
당기거나 상단 검색을 누른다.

기존 `Navigate: Search Space`와 `Ctrl-K`를 버리지 않고 새 검색 화면의 기반으로 삼는다. 먼저
제목·본문 범위와 결과 순서를 실측하고, 키보드가 없는 화면에서도 검색에 들어갈 길을 복구한다.

검색 전에는 최근 수정 문서를 보여준다. 입력을 시작하면 제목과 본문을 함께 찾고,
결과마다 검색어가 나온 문장·폴더·수정 날짜를 보여준다. 첫 릴리스는 입력한 낱말과 문구가
그대로 들어 있는 결과를 대상으로 하며, 오타 교정과 유사어 검색은 후속으로 둔다. 왜 나온
결과인지 알 수 있도록 일치한 부분을 표시한다.

```text
무엇을 찾을까요?
회의록 김수리

최근 문서
  주간 회의록

검색 결과
  킥오프 회의록
  회의록/2026 · “…김수리에게 시안 확인 요청…”

  제품 회의
  회의록/2026 · “…회의록 작성 방식 결정…”
```

결과는 기본적으로 제목과 본문을 함께 찾는다. 선택 필터는 `폴더`, `날짜`, `할 일` 세 가지다.
결과가 없으면
입력한 말을 제목으로 새 문서를 만들 수 있다. 검색은 파일의 별도 복사본을 정본으로 만들지 않고,
Markdown 볼트에서 다시 만들 수 있는 색인만 사용한다.

## 입력 문법

### `@`: 이미 의미가 있는 것을 넣는다

날짜 자동완성은 이미 구현되어 있다. 새 작업은 현재 동작을 그대로 보존하고 발견하기 쉽게
보여주는 것이다. 페이지 연결은 `@`에 추가하지 않는다.

| 입력 | 결과 |
|---|---|
| `@today`, `@tomorrow`, `@yesterday` | 표준 형식의 날짜, **이미 구현됨** |
날짜 후보의 이름과 설명은 한글로 보여준다. 날짜 범위를 늘리는 일은 후속이다. 페이지 연결은
`[[` 하나로 통일해 초보자가 `@`와 `[[` 중
무엇을 써야 할지 고르게 하지 않는다.

### `/`: 만들거나 실행한다

| 묶음 | 첫 명령 |
|---|---|
| 쓰기 | `/text`, `/h1`, `/h2`, `/todo`, `/bullet`, `/quote`, `/code`, `/divider` |
| 정리 | `/link`, `/toc`, `/template`, `/move` |
| 할 일 | `/due`, `/repeat`, `/priority` |

현재 SilverBullet의 슬래시 트리거는 ASCII 명령 이름만 받는다. 따라서 `/due`, `/todo`처럼
입력하되 결과 이름과 설명은 한글로 보여준다. 한글 명령 입력을 지원하려면 기본 트리거를
대체하는 별도 IME 입력 기반이 먼저 필요하며, 이번 캠페인에는 넣지 않는다. 현재 커서에서
쓸 수 없는 명령은 숨긴다.

### `[[`: 페이지를 연결한다

`[[`를 입력하면 기존 페이지를 찾고, 없으면 새 페이지를 만든다. 링크는 마우스를 올리거나
키보드로 초점을 맞추거나 길게 눌렀을 때 간단한 미리보기를 보여준다. 백링크가 있으면 제목
근처에 `3개 문서에서 언급`처럼 표시해 그래프 패널을 열지 않아도 관계를 발견하게 한다.

## 할 일 경험

파일에는 계속 읽을 수 있는 Markdown이 남는다.

```markdown
- [ ] 제안서 보내기 📅 2026-09-12
```

편집 화면에서는 날짜를 사람이 읽는 말로 보여준다. 할 일 줄에 커서를 두면 `오늘`, `내일`,
`날짜`, `반복`, `더보기`가 작게 나타난다. `/due`를 다시 실행하면 기존 기간을 교체하고,
완료 직후에는 실행 취소를 제공한다. 지난 날짜는 `3일 지남`처럼 읽힌다.

반복과 우선순위는 단일 날짜와 기간이 안정된 다음에 추가한다. 새 표시를 만들더라도 원본
Markdown에서 뜻을 짐작할 수 있어야 한다.

## 첫 사용과 빠른 메모

빈 줄에는 `내용을 입력하거나 '/'로 기능 열기`를 보여준다. 빈 페이지에서는 모달을 띄우지 않고
문서 안에서 `빈 문서`, `템플릿`, `오늘 일지` 중 하나를 고르게 한다.

빠른 메모는 전역 단축키나 모바일 하단 행동 영역에서 작은 입력창으로 열린다. 저장 위치는
`받은 메모`, `할 일`, `오늘 일지`다. 기본값은 받은 메모로 두어 처음부터 폴더 구조를 결정하게
하지 않는다. 정리는 나중에 `/move`로 한다.

## 구현 순서

### A. 문서 통합검색

- 제목과 본문을 한 검색창에서 찾는다.
- 결과에 일치 문장·폴더·날짜를 보여준다.
- 검색 전에는 최근 수정 문서를 보여준다.
- 폴더·날짜·할 일 필터와 결과 없음에서 새 문서 만들기를 제공한다.
- 데스크톱과 모바일에서 같은 검색 결과를 검증한다.

### B. 일관된 입력 동작

- `@`, `/`, `[[`는 각자의 기존 트리거를 유지한다.
- 메뉴 모양, 키보드 이동, 터치, 취소 동작과 한글 본문 조합 중 텍스트 보존 규칙을 맞춘다.
- 한글 슬래시 별칭과 한글 명령 검색은 이번 캠페인에서 제외한다.
- 텍스트 삽입과 기능 실행을 구분하고 안전한 실행 취소를 제공한다.
- 기존 `@today`와 `/due`를 저장 형식 변경 없이 새 기반으로 옮긴다.

### C. 매일 쓰는 기능

- 기존 `@날짜`를 유지한다.
- `[[`에서 페이지 생성과 미리보기를 제공한다.
- 기본 Markdown, 링크, 템플릿, 할 일 동작을 슬래시 메뉴에서 검색한다.
- 기존 Markdown 형식을 보존하며 할 일 날짜를 화면에서 바꾼다.

### D. 처음 쓰는 사람

- 빈 줄과 빈 페이지가 다음 행동을 알려준다.
- 문서 안에서 템플릿을 고른다.
- 받은 메모, 할 일, 오늘 일지로 빠르게 기록한다.
- 모든 핵심 행동을 모바일에서도 같은 수준으로 제공한다.

### E. 공개 릴리스

- Folio 이름과 작업공간 기능을 하나의 공개 앱 산출물로 배포한다.
- 설치, 업그레이드, 롤백, 제거, 기존 볼트 보존을 수명주기 테스트로 확인한다.
- 처음 쓰는 사람이 도움말을 읽지 않고 인수 여정을 마친다.

## 인수 여정

처음 쓰는 사람이 데스크톱과 모바일에서 도움말을 열지 않고 다음을 끝낸다.

1. 빈 작업공간에서 페이지를 만든다.
2. 제목을 기억하지 못하는 문서를 본문의 단어로 검색해 찾는다.
3. 최근 문서를 열고 폴더·날짜 필터로 결과를 좁힌다.
4. `@today`를 입력한다.
5. `[[`로 기존 페이지를 연결한다.
6. `/todo`로 할 일을 만들고 날짜를 붙이고 바꾸고 완료한 뒤 취소한다.
7. `[[`로 없는 페이지를 만든 뒤 백링크를 따라 돌아온다.
8. 빠른 메모를 받은 메모에 저장한 뒤 폴더로 옮긴다.
9. Folio를 닫았다 다시 열어 같은 Markdown 내용과 검색 결과를 확인한다.

콘솔 오류, 글자 손실, 중복 입력이 없어야 한다. 터치 기기에서 hover가 필요한 기능도 없어야 한다.

## 이번에 하지 않는 것

- Notion식 데이터베이스, 수식, 속성, 임의 블록 중첩
- 실시간 공동 편집
- 사람 언급, 댓글, 공유 받은함, 서버 푸시 알림
- 마켓플레이스와 제3자 제공자 API
- AI 글쓰기
- 메일 작성·수신·발송·메일함 연동

필요해지면 각각 별도 캠페인으로 다룬다. 지금 처음 쓰는 개인 사용자의 경험을 완성하는 데에는
필요하지 않다.
